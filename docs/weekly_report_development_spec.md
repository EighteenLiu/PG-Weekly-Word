# 平谷区垃圾分类周报生成程序开发文档

## 一、项目目标

开发一个桌面端单窗口周报生成程序，用于根据本周区级基础台账、市级检查台账、Jinja DOCX 模板和街乡镇分组清单，自动生成《平谷区垃圾分类桶站检查情况通报》Word 文档。

输出文档必须完全沿用上传的 DOCX 模板版式；正文内容只通过 Jinja 占位符替换和循环渲染生成，不允许在代码里重新搭建另一套 Word 样式。

## 二、用户操作流程

1. 打开桌面端单窗口程序。
2. 上传“区级基础台账”。
3. 上传“周市级检查台账”。
4. 上传“Jinja 周报模板 DOCX”。
5. 上传或选择“平谷区街乡镇分组清单.xlsx”，或通过“新增点位”手动维护后台固定分组 JSON。
6. 选择输出目录和报告周期。
7. 点击生成。
8. 后台先由基础台账生成区级问题台账，再完成统计、渲染模板并输出 DOCX。

界面必须显示每个文件的校验状态、识别到的检查周期、问题总数、检查点位数、区级排名表预览和生成结果路径。

## 三、输入文件

### 1. 区级基础台账

示例：`7月4日-7月10日基础台账.xls`

读取第一个工作表，从第 3 行开始为数据行。关键列如下：

| 列 | 含义 | 用途 |
|---|---|---|
| 2级点位 | 小区 / 村居 | 统计小区和村居数量 |
| 3级点位 | 街乡镇 | 归属乡镇街道 |
| 4级点位 | 上级点位名称 | 不作为检查数量主口径 |
| 5级点位 | 实际检查点位 | 检查数量主口径 |
| 具体问题 | 具体问题文本 | 判断是否为无问题记录、生成问题台账 |
| 2级指标 | 区级问题类型 | 区级问题分类统计 |
| 3级指标 | 细分问题 | 区级具体问题统计 |
| 上报时间 | 检查时间辅助字段 | 可用于校验周期 |

检查数量口径：按“3级点位 + 5级点位 + 2级点位”去重。最新样例中该口径得到 102 个小区、22 个村居，合计 124 个检查点位。

### 2. 周市级检查台账

示例：`7.2---7.5(1).xlsx`

使用本周对应工作表，并在选定工作表后按照市级周期筛选 `日期` 列；只有周期内的记录参与市级统计。所选工作表在周期内无匹配记录时停止生成并提示重新选择工作表或修正周期。示例文件中 Sheet4 对应 07.02-07.05 市级检查。关键列：

| 列 | 含义 |
|---|---|
| 日期 | 市级检查日期 |
| 乡镇街道 | 归属乡镇 |
| 小区/村 | 点位 |
| 大类问题 | 市级问题大类 |
| 问题 | 具体问题描述 |
| 第 7 列空表头 | 问题数量 |

程序应允许用户在界面选择工作表；默认选择最后一个含数据工作表。

### 3. 街乡镇分组清单

示例：`平谷区街乡镇分组清单.xlsx`

两列：`分组`、`街乡镇`。分组列存在空值时，沿用上一行分组。用于“平谷区垃圾分类现场检查问题率排名表”和区级重点乡镇段落。

界面应提供“新增点位”按钮，弹窗包含“城乡镇”和“分组”两个字段。点击新增后写入 `docs\平谷区街乡镇分组清单.json`；如果当前上传了 Excel 分组清单，生成时仍优先使用上传文件，并按既有逻辑同步 JSON。

### 4. Jinja DOCX 模板

示例输出模板：`input/周报模板.docx`

使用 `docxtpl` 渲染，不允许改动参考样例原件。

## 四、区级问题台账生成规则

后台从基础台账生成问题台账，不要求用户上传问题台账。

保留规则：

1. 保留存在实际问题的记录。
2. 剔除无问题记录，例如“查N错0”、`没问题`、`无问题`等。
3. 输出问题台账字段应至少包含：编号、1-5级点位、1-3级指标、具体问题、上报时间、图片字段。
4. 生成的问题台账作为内部临时文件用于行数校验，写入项目内 `work\tmp` 的单次临时目录，周报生成结束后自动清理。

最新样例中基础台账 535 条有效记录，问题台账 534 条有效记录，区级问题总数为 534。

## 五、统计规则

### 1. 总体情况

市级总体：

- 检查乡镇数：市级台账中 `乡镇街道` 去重。
- 检查点位数：市级台账中 `乡镇街道 + 小区/村` 去重。
- 分乡镇点位数量：按乡镇统计点位去重数。
- 市级问题总数：市级台账第 7 列问题数量求和。

区级总体：

- 检查乡镇数：基础台账中 `3级点位` 去重。
- 小区数：基础台账中 `2级点位=小区` 时，按 `3级点位 + 5级点位` 去重。
- 村居数：基础台账中 `2级点位=村居` 时，按 `3级点位 + 5级点位` 去重。
- 区级问题总数：后台生成的问题台账有效行数。

### 2. 市级六大类问题

周报固定展示六类：

1. 居民投放情况
2. 值守指导
3. 投放点情况
4. 大件垃圾投放点
5. 规范管理
6. 小区公示牌

市级台账原始大类需要归并：

| 原始大类关键词 | 归并大类 |
|---|---|
| 居民投放、居民自主投放 | 居民投放情况 |
| 值守 | 值守指导 |
| 投放点情况、环境脏乱 | 投放点情况 |
| 大件垃圾投放点 | 大件垃圾投放点 |
| 居民询问情况 | 规范管理 |
| 小区公示牌、村公示牌、投放点公示牌、公示牌 | 小区公示牌 |

每类输出问题数、占比、主要问题、问题突出的乡镇。数量为 0 时按样例写“经上周期问题整改后持续保持良好状态，本周期未发现相关问题。”

六大类重点检查问题段落中，“问题突出的乡镇是”后面的 `乡镇街道+数量` 文本应加粗，例如 `滨河街道9处`、`黄松峪乡4处`。

### 3. 市级问题集中区域

按乡镇汇总市级问题数量，取问题数最高的乡镇。通常取前 2-3 个；若前几名合计占比较高，应生成“以上N个乡镇占市级总问题数X%”。

每个乡镇段落列出该乡镇各大类问题数量，按问题数降序。

### 4. 区级问题分析

区级问题类型使用问题台账 `2级指标` 字段。统计分析时将“容器满冒”和“容器整洁率”合并为“容器满冒脏污”，数量为两类问题数量之和；导出问题台账仍保留原始指标名称。

区级总述取全区问题数前三类，形成：

`本周期累计发现问题{{ district_total_issues }}处，突出问题为{{ top1.name }}{{ top1.count }}处（占比{{ top1.percent }}%）、{{ top2.name }}{{ top2.count }}处（占比{{ top2.percent }}%）、{{ top3.name }}{{ top3.count }}处（占比{{ top3.percent }}%）。其中，城区组主要问题为...，平原组主要问题为...，山区组主要问题为...。`

各组主要问题取该组问题数前 2 类。

### 5. 问题率排名表

使用分组清单确定组别。每个乡镇：

- 问题数：区级问题台账中该乡镇问题行数。
- 检查小区、村：基础台账中该乡镇 `5级点位` 去重数量。
- 问题率：`问题数 / 检查小区、村`，保留两位小数。
- 排名数字：组内按问题率从低到高赋值，问题率最低为 1。
- 表格展示顺序：按城区组、平原组、山区组分组展示；每组内部按问题率从高到低展示。因此样例中城区组“兴谷街道”问题率最高，显示在城区组第一行，但排名数字为 3。
- 表格中每个组别展示顺序的第一行整行加粗。
- 总体情况图表中的平均值折线应使用全区整体问题率，即 `总问题数 / 总检查小区、村数`，不乘 100，并在最后一个点显示 `仿宋_GB2312` 10 号加粗的平均值数字标签；纵轴最大值取大于等于最高值的下一个 5 倍数，刻度间隔固定为 5。

区级重点乡镇段落取每组问题率最高的乡镇：

- 城区组 1 个
- 平原组 1 个，同时如果它也是全区最高，写“位列本周检查乡镇问题率首位”
- 山区组 1 个

每个乡镇段落列出该乡镇问题数前三到四类。

## 六、“下一步重点工作”生成库

生成时从市级六大类问题中按问题数降序选择前四类；如果某类问题数为 0，不进入候选。每个方向使用固定标题，正文按本周实际出现的具体小问题，从措施句库中动态选择并组合，不再套用整段固定正文。措施句库优先使用已有周报中对应问题的原话；已有周报缺少对应问题表述时，才使用补写兜底句。

| 对应大类 | 固定标题 |
|---|---|
| 居民投放情况 | 强化源头分类引导，提升居民自主投放准确率 |
| 值守指导 | 压实桶前值守责任，提升现场分类指导质效 |
| 投放点情况 | 加强桶站设施管理，改善投放环境面貌 |
| 大件垃圾投放点 | 规范大件垃圾及驿站管理，补齐设施短板 |
| 规范管理 | 健全长效管理机制，压实各方工作责任 |
| 小区公示牌 | 规范公示信息管理，提升信息准确性 |

具体问题按问题数降序处理，每段最多选择 3 条不重复措施句；只有 1 种实际问题时只输出 1 条，不补通用句。多个问题匹配同一措施句时只输出一次。完整匹配库见《周报生成逻辑汇总.md》。市级具体问题不足时，可结合区级重点问题补充同方向措施句。

## 七、模板变量

模板文件使用以下变量：

| 变量 | 类型 | 含义 |
|---|---|---|
| report_year | 字符串 | 年份，如 `2026` |
| city_period_short | 字符串 | 市级周期，如 `07.02-07.05` |
| district_period_short | 字符串 | 区级周期，如 `07.04-07.10` |
| city_overview | 字符串 | 市级总体情况段落 |
| district_overview | 字符串 | 区级总体情况段落 |
| city_six_categories | 列表 | 市级六类表格数据 |
| city_six_category_paragraphs | 列表字符串 | 市级六类分析段落 |
| city_concentrated_area_summary | 字符串 | 市级集中区域总述 |
| city_concentrated_area_paragraphs | 列表字符串 | 市级集中区域逐乡镇段落 |
| district_issue_summary | 字符串 | 区级问题总述 |
| district_top_town_paragraphs | 列表字符串 | 区级重点乡镇段落 |
| district_rank_rows | 列表 | 区级问题率排名表 |
| next_work_items | 列表 | 下一步重点工作四条 |

`city_six_categories` 每项字段：`name`、`count`、`description`。

`district_rank_rows` 每项字段：`group`、`rank`、`town`、`issue_count`、`checked_count`、`issue_rate`。

`next_work_items` 每项字段：`cn_index`、`title`、`body`。

## 八、桌面程序建议

建议使用 Python + PySide6 或 Python + Tkinter。若优先打包稳定性，可用 Tkinter；若优先界面观感，可用 PySide6。

核心依赖：

| 依赖 | 用途 |
|---|---|
| docxtpl | 渲染 Jinja DOCX 模板 |
| jinja2 | docxtpl 必需依赖 |
| xlrd | 读取 `.xls` 基础台账 |
| openpyxl | 读取 `.xlsx` 市级台账、分组清单，输出问题台账 |
| python-docx | 模板结构检查、必要时做 DOCX 结构校验 |
| PySide6 或 tkinter | 桌面端单窗口界面 |

窗口区域：

1. 文件选择区：基础台账、市级台账、模板、分组清单、输出目录。
2. 参数区：区级周期、市级周期、市级工作表选择。
3. 校验区：显示台账列识别、统计摘要、异常提示。
4. 预览区：显示市级六大类、区级排名表、下一步工作四条。
5. 操作区：生成问题台账、生成周报、打开输出目录。

## 九、校验和异常

必须校验：

- 基础台账是否含 2级点位、3级点位、5级点位、具体问题、2级指标、3级指标。
- 市级台账是否含 日期、乡镇街道、小区/村、大类问题、问题、问题数量列。
- 分组清单中所有基础台账乡镇是否都有分组。
- 渲染前所有模板变量是否存在。
- 生成的问题台账行数是否等于区级问题总数。

遇到缺列、无法识别工作表、乡镇未分组、模板变量缺失时，程序应停止生成并在界面中给出中文错误提示。

## 十、输出文件

输出目录下至少生成：

1. `2026年平谷区垃圾分类桶站检查情况通报（周期）.docx`

`问题台账（周期）.xlsx` 和 `生成统计摘要（周期）.json` 仅作为生成过程临时文件写入项目内 `work\tmp`，生成结束后自动清理，不保留在正式输出目录。

默认不打包、不压缩。

## 十一、开发约束

- 未经允许不得修改参考通报、用户上传模板或原始台账。
- 临时文件、缓存、构建文件必须放在项目目录或用户选择目录，不得写入 C 盘临时目录。
- 每次修改代码后检查 README 或说明文档是否需要同步。
- 打包时除非用户明确要求，不生成压缩包。
- 发布打包使用 `python build_release.py`，生成 `release\平谷周报生成工具\平谷周报生成工具.exe`，并随带 `docs`、`input` 和 `README.md`。
